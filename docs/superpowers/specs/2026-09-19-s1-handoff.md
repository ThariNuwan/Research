# S1 → S2/S3 handoff: residual risks and what they cost

**Status:** written at the close of S1, 2026-09-21
**Spec:** `2026-09-19-s1-preimplementation-artifacts-design.md`
**Plan:** `../plans/2026-09-19-s1-preimplementation-artifacts.md`

S1's artifacts are green, test-pinned and structurally frozen. This document records what they do **not** guarantee, so the next sub-project inherits the gaps explicitly rather than rediscovering them. Every item below is either a live risk or a lesson that cost something to learn.

---

## 1. The rubric's citation text is not audited

`src/iacrisk/data/rubric.json` carries `citations_audited: false`, deliberately separate from `structure_frozen: true`.

The structural freeze is earned: six factors, their ranges, the 1–28 bounds and the band boundaries were fixed before any scoring output existed, were computed rather than asserted, and are pinned by tests. **The citation text has no comparable evidence.** The verification pass described in spec §3.1 ran during design against a working file; its corrections were written into spec §3.4 as "applied" and did not reach `rubric.json` for a month — all fourteen of them, in the artifact the dissertation mirrors verbatim and which had already been marked frozen.

**Before any dissertation text quotes a `source` string:** audit all 33 levels against the primary sources and commit the audit — the quoted text, the source document and section, and a verification date. Then flip the flag. This is scoped work, not a test.

## 2. The anchor gate cannot do that job

`test_every_level_is_source_anchored_and_justified` and gate 2 check that a level's `source` *contains* one of `CVSS`, `NIST`, `NSA`, `OWASP`, `FIPS`. That is all they can check. They are structurally blind to a wrong appendix, an inverted metric, a misquote, or a plausible-sounding invention.

Do not read a green suite as evidence of citation soundness. It is evidence that a standard's *name* appears in the string.

## 3. The failure mode that produced items 1 and 2

Every verification on the S1 branch asserted that `rubric.json` was **byte-identical to its design input**. The corrections had never been applied to that input either, so the check compared uncorrected text against itself. It could not fail for the reason that mattered, and it was the check the controller was most confident in.

**The generalisable rule:** a verification that compares an artifact to its own provenance establishes *transcription fidelity*, never *correctness*. When the property you care about is correctness against an external source, provenance comparison is not evidence — and it is worse than no check, because it reads as one.

Six per-task reviews missed this. It was found only by a whole-branch pass positioned to compare the spec's claims against the artifact's contents.

## 4. `class_id` is a router, never an addend

PLAN Q9 says the encryption/severity overlap rule is *keyed on* issue-class. The rubric's `severity_context_fencing` coherence rule says **`class_id` is never a term in the score**. These reconcile — keyed-on is not additive — but S3 implements both and must keep the boundary sharp.

The `unmapped:` contract already makes class a scoring *router* (`severity-only, default context`). That is the shape to preserve. An `assert class_id not in score_terms`-style test at the scoring layer is the S3 form of `test_class_id_is_not_a_term_in_the_score`, which S1 could only assert structurally.

## 5. `normalize_severity` returns `int | str`

The string is the explicit `unknown` state, and it is a first-class value, not an error. **Every S3 call site must branch on it before arithmetic** — a single unguarded `+` silently concatenates or raises at runtime rather than scoring.

Consider converting at the adapter boundary into something the type system enforces (a sentinel type, or an explicit `(level, is_unknown)` pair) so the branch cannot be forgotten in one of many call sites.

## 6. `normalize_path` is best-effort outside its scope

`identity.normalize_path` is scoped to scanner-emitted **relative** paths. Nothing rejects an absolute or UNC path: `lstrip("/")` on `C:\foo\bar` leaves the drive letter, and the context-join then misses silently — the exact failure the function exists to prevent.

Corpus v0's scanner output is relative throughout (verified: 1129 path strings, 103 distinct spellings, all relative). If an S3 adapter can ever produce an absolute path, reject it or count it as `unresolved` at the adapter rather than letting it through.

## 7. The default-fallback washout is arithmetically live

Spec §3.5(2) notes the five context defaults sum to 16, so an all-defaulted finding lands 17–21 — **always High**, regardless of what it is.

The ground-truth schema now distinguishes `defaulted_factors` (PLAN Q4, a missing *declared* value) from `unresolved_factors` (PLAN Q9, an *extractor* failure), which is what makes §3.5(2)'s split-by-defaulted-count report producible. **Use both fields when authoring the corpus in S2** — merging them, or leaving them empty, makes the report impossible after the fact.

## 8. No committed generator for the two data artifacts

`taxonomy.json` and `rubric.json` were produced by one-shot scripts that were never committed, so there is no reviewable path from input to artifact. This was deliberate — the committed artifacts are the source of truth and their invariants are pinned against `artifacts/rule-inventory.json` — but it means a future change to either is a hand edit.

That is acceptable for an erratum and **not** acceptable for a re-tune. If S3 or S4 ever needs a structural change to the rubric, write and commit the generator first, so the change has a diff someone can review.

## Two process lessons, recorded because they cost real time

**Correcting an erratum means grepping the tree for the wrong value, not fixing the sentence that surfaced it.** The `AWS-0088` twin example — a rule trivy does not emit — was corrected in spec §2.2, then found again in spec §2.1's code block three lines above, then again in `taxonomy.py`'s own docstring. Three passes for one wrong value, because each fix addressed the occurrence in front of it.

**A test's name is a claim, and claims need checking against the body.** Nine §G3 defects surfaced across S1 — a test named `…_and_additive` that never asserted the formula, one named `…matches_the_harvest` that never read the harvest, one asserting an "omitted namespace" while passing one explicitly, a docstring citing a test that recorded nothing of the kind. **Every one was inherited from the plan or the spec; none was introduced by an implementer.** Writing the plan is where this defect class enters, and reviewing the plan against itself is cheaper than finding them one task at a time.
