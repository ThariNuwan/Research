# S4 handoff — residual risks

**Sub-project:** S4, pipeline layers 4 and 5 (scoring, banding, ranking, reporting).
**Spec:** `docs/superpowers/specs/2026-10-01-s4-scoring-reporting-design.md`
**Plan:** `docs/superpowers/plans/2026-10-01-s4-scoring-reporting.md`
**Gates:** `tests/test_s4_gates.py` — eight, all green. 820 tests in the suite.
**Read this before starting S5 or S3c.**

Every figure below was measured on this host at `6186f3c` against the committed fixtures and
`corpus-v1`'s declared context. Each item says what it costs if ignored.

---

## 1. Zero findings reach Critical, and the reason is structural

The measured band distribution over all 1,055 findings:

| Band | Count | Share |
|---|---|---|
| Critical | **0** | 0.0% |
| High | 555 | 52.6% |
| Medium | 466 | 44.2% |
| Low | 34 | 3.2% |

**The framework never says "block deployment" on corpus v0.** This is not degenerate — three
bands are populated and the re-ranking against the baseline is substantial (§4) — but the top
band is empty, and the cause is arithmetic rather than incidental.

**The all-defaults total is exactly 20, two short of Critical's 22.** So a finding with
nothing resolved can never be Critical. Reaching 22 requires resolved values *above* the
defaults on several factors simultaneously.

**Cost if ignored:** presenting the four-band model as exercised when one quarter of it is
untested by any real finding. `rubric.band_for`'s Critical branch is reached only by unit
tests. Any dissertation claim about Critical-band behaviour rests on constructed examples, and
the write-up must say so.

## 2. Resolving a factor typically LOWERS its contribution

This is the most important thing S4 measured, and it inverts the intuition the model invites.
Five of the six factors have a mean resolved value **below** their conservative unresolved
default:

| Factor | Unresolved default | Resolved n | Mean resolved | Direction |
|---|---|---|---|---|
| `privilege` | 4 | 685 | **0.01** | far below |
| `encryption` | 2 | 340 | **0.00** | far below |
| `sensitivity` | 3 | 67 | **1.33** | below |
| `criticality` | 4 | 201 | **2.44** | below |
| `severity` | 4 | 370 | **2.53** | below |
| `exposure` | 3 | 55 | 3.04 | marginally above |

**So an unresolved finding outranks a resolved one of the same actual risk.** That follows
directly from PLAN Q9 — a missing value must never read as low, so the defaults are
deliberately conservative — but the consequence is a ranking artefact, not a safety property:
the findings the extractor understands best are pushed *down* relative to the ones it
understands least.

The washout is visible directly in the distribution split by defaulted-factor count: the
**largest single bucket is 5-missing at 415 findings, every one scoring exactly 20, all
High**.

**Cost if ignored:** every prioritization-quality claim is affected. A reader comparing two
findings cannot tell whether the higher-ranked one is riskier or merely less understood. This
belongs in the write-up's limitations **and** is the first thing Q10's sensitivity analysis
should probe — sweeping the five `unresolved_default` values is a more consequential
experiment than sweeping the band thresholds.

## 3. The factor-gap sweep found 14 classes, not the 5 `CLAUDE.md` names

`CLAUDE.md` names three classes with a further two as candidates, and states the set "is not
established as complete — a systematic 28-class × 6-factor sweep is S4's". **The sweep ran,
and `CLAUDE.md` is now stale on this point.** Measured:

- **14 of 28 classes** are factor gaps.
- **434 of 1,025 eligible findings (42.3%)**, against the 122 (11.9%) the five-class estimate implied — **3.6×**.
- Split by a textual test on each class's own definition: **4 classes / 178 findings (17.4%)** self-declare as "lower-severity" or "no direct … impact", and **10 classes / 256 findings (25.0%)** do not.

**25.0% is the figure the write-up carries.** Folding the 17.4% in would nearly double the
apparent limitation, in the same way reporting Tier-2's 91 same-scanner candidates as
cross-scanner overlap would.

The spec's §2.1 ruling — do not widen the factor set — survives the larger number and is
argued on it. The decisive reason: the missing dimensions are **eight unrelated ones**
(recoverability, image provenance, container escape, audit visibility, identity management,
metadata credential theft, egress exfiltration, CVE scanning), so closing them needs roughly
five new factors and a new ceiling. That is a different framework, not an adjustment.

**Cost if ignored:** a dissertation that cites `CLAUDE.md`'s three classes understates its
own largest limitation by a factor of three and a half.

## 4. The framework re-ranks substantially, and the baseline's coverage must travel with it

The framework-band × baseline-band contingency table, counts only:

| Movement | Count |
|---|---|
| baseline High → framework Medium | 270 |
| baseline High → framework High | 402 |
| baseline Low → framework Medium | 102 |
| baseline Low → framework High | 93 |
| baseline Medium → framework Medium | 88 |
| baseline Medium → framework High | 50 |
| baseline Critical → framework High | 10 |
| baseline Critical → framework Medium | 6 |
| baseline High → framework Low | 13 |
| baseline Medium → framework Low | 9 |
| baseline Low → framework Low | 12 |

So the layer does real work: 270 demotions out of baseline-High, 195 promotions out of
baseline-Low, and **all 16 baseline-Critical findings demote**, which is the §1 truncation
seen from the other side.

**But 489 of 1,055 findings (46.4%) reach their baseline band through the unknown-severity
route**, banding as High on the rubric's `unknown_resolves_to` of 4. That figure must be
reported with every baseline comparison. Without it a reader cannot tell how much of
"baseline High" is a measurement and how much is a default.

**Cost if ignored:** the rank-change table reads as 270 corrected mis-prioritizations when
an unknown share of the baseline column was never a scanner judgement at all.

## 5. `factor_map.json`'s 168 cells are an authored judgement, reproducibly made

The artifact carries its authoring rule as data and every entry carries a rationale, and a
test asserts each gap entry says so explicitly. That makes the judgement **checkable and
re-derivable** — it does not make it **proven**. This is precisely the shape of S2's
single-factor-purity caveat, one level up.

Two cells are deliberate and counter-intuitive, and a reviewer should attack them first:

- **`iam-authentication-controls` does not bear `privilege`.** It describes *how* identity is managed, not how much it grants. The S2 handoff names this exact class as one that reads as factor evidence and is not.
- **`storage-data-recoverability` does not bear `encryption`**, despite that factor being named "required encryption / data-protection missing". Every one of its levels is specific to encryption at rest or in transit; recoverability is an availability property no level describes. At 67 findings it is the largest substantive gap, so this cell going the other way would hide the biggest one.

**Cost if ignored:** one wrong cell moves the gap count off 14 or the substantive count off
10, and both are headline dissertation figures.

## 6. The gap population is counted over context-eligible findings only

`report.build` first counted 446 gap findings; the gate counted 434. The 12 difference are
**context-ineligible** findings whose class happens to be a gap class — already excluded as
`baseline_only_informational`, and carrying no context factors at all. Counting them inflated
one limitation with findings excluded for a different reason.

`factor_gap` on `ScoredFinding` remains a property of the **class**, so the engine sets it
either way; only the report's population is gated. A test pins this with the 446-vs-434
figure in its docstring.

**Cost if ignored:** the two-exclusions-conflated error this project has now hit three times
(Tier-2 cross/same-scanner, declared/all-v0 resolution rates, and here).

## 7. `exposure` contributes a flat 3 to 970 of 1,025 findings

Carried forward from S3b and now measured at the contribution level. Exposure's contribution
distribution is `{0: 9, 1: 5, 2: 1, 3: 970, 4: 40}` — of which 934 are the unresolved default
and 36 are resolved values that happen to equal it.

**So exposure does almost no ranking work**, which §7.3's per-factor summary is designed to
make visible. It discriminates *within* PLAN Q9's closed supported-pattern list and is
`unresolved` outside it, never low.

**Cost if ignored:** presenting a 0–5 factor as a working discriminator when it is
near-constant on 95% of findings.

---

## 8. Gate 4b's orthogonality mutation is weaker than gate 4a's

Gate 4a asserts that no contribution changes under an `issue_class` mutation — a strong
negative over 1,055 findings × 6 factors. Gate 4b varies declared `sensitivity` between 0 and
5 and asserts that only the sensitivity contribution moves, plus `moved > 0`.

`moved > 0` is a weak existence check. It confirms the mutation reached *something*, not that
it reached everything it should: only resources `corpus-v1` actually declares can move, which
is 20 identities.

**Cost if ignored:** a future change that stopped reading declared sensitivity for most
resources would keep `moved > 0` true and pass.

---

## 9. Weights are implemented but unexercised outside the refusal test

`score(..., weights=...)` exists so S5's sensitivity analysis need not fork the engine, which
would risk the analysed model drifting from the scored one. `emit.to_json` refuses to emit
over weighted scores, and gate 8 asserts that refusal. But **no production path produces a
weighted score**, so the multiply itself is exercised only by tests.

**Cost if ignored:** S5 will be the first real consumer. Verify the weighted arithmetic
against a hand-computed example before reporting any weighted result.

## 10. Deferred, unchanged

**To S5:** the independent harness and every evaluation metric — normalization/retention
coverage, prioritization usefulness against the pre-registered oracle, alert reduction as two
separate numbers, ranking consistency as two separate measures, the baseline **comparison
statistics**, and the Q10 sensitivity analysis. S4 emits the JSON; it computes no metric.

**To S3c:** the convention-based auto-inference mode and the auto-inference agreement metric.

**Still named future work, not attempted:** cross-scanner attribute normalization (S3a §13), a
measured `raw_records_seen` to replace S3a's derived `findings_in`, Helm rendering before
Kubernetes indexing (S3b handoff item 3), and the IAM role → attachment → policy aggregation
(S3b handoff item 5).

**One documentation task that is not optional.** `CLAUDE.md` still says three taxonomy classes
map to no rubric factor and that the sweep is S4's to run, and `docs/writeup/03-framework-design.md`
§3.10 still describes layer 3 as "specified … not yet implemented" and cites 3,097 lines and
641 tests. Both are now false. The chapters are written from the measured record, so a figure
that changes in an artifact must change there too.
