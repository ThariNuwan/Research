Results overview

Risk-aware prioritization of IaC security misconfigurations

Rule-based scanners report many misconfigurations with a flat severity label. This framework sits on top of three of them and re-ranks what they find, using six inspectable factors about the affected resource. This page shows what the evaluation found, with the qualification that belongs to each result.

The framework

What it does

A five-layer pipeline. Detection is left to the existing scanners; the contribution is the prioritization layer on top of them.

1

IaC input

Terraform files and Kubernetes manifests.

2

Security scanning

Checkov, tfsec and Trivy run unchanged. Their findings are normalized and exact duplicates merged.

3

Context extraction

Exposure, privilege and encryption are read from the code. Sensitivity and criticality are declared.

4

Risk scoring

A transparent additive score. No machine learning: every point is attributable.

5

Reporting

A ranked list in four priority bands, with one explanation line per factor.

Score =Severity1–5+Exposure0–5+Privilege0–5+Sensitivity0–5+Criticality0–5+Encryption0–3 from 1 to 28
Low1–8Monitor / document / fix when convenient
Medium9–15Schedule in normal sprint/backlog
High16–21Fix before production / require approval
Critical22–28Block deployment, remediate immediately

A factor that cannot be read from the code is never treated as low. It takes a stated default (severity 4, exposure 3, privilege 4, sensitivity 3, criticality 4, encryption 2) and is marked as a default wherever it is shown.

Result 3

How stable are the results?

63 variants of the model were registered before any was computed: every unresolved default across its range, every band boundary moved by one and two points, every factor dropped and doubled. All 63 are reported.

The ordering results hold

  • The pair result is unchanged in 59 of 63 variants. It moves only when the factor a pair tests is removed altogether.
  • The number of exactly matched scenarios is unchanged in 56 of 63.

The band counts do not

  • Moving the High boundary one point changes the Critical/High count from 235 to 36 or 296.
  • With every default at its minimum the count is 0; at its maximum, 907.

Why aws_iam_policy.unrestricted_scope scores 18

  • severity: 4 (unresolved, the rubric default) - checkov supplied no severity ('unknown'); scored at the rubric default
  • exposure: 3 (unresolved, the rubric default) - aws_iam_policy matches no supported exposure pattern (security-group ingress, public flag, bucket publicness, K8s Service/Ingress)
  • privilege: 5 (resolved) - aws_iam_policy.unrestricted_scope.policy: highest Allow statement scores 5
  • sensitivity: 3 (resolved) - declared context for aws_iam_policy.unrestricted_scope
  • criticality: 3 (resolved) - declared context for aws_iam_policy.unrestricted_scope
  • encryption: 0 (resolved) - aws_iam_policy holds no data at rest within this framework's scope

Produced by uv run iacrisk <folder> --declared context.json, which runs the three scanners live. Where the scanners are installed, a test scans both corpus folders again and requires the recorded scores back, finding for finding.

Conclusion

What the evidence supports, and what it does not

Supported

  • Context separates findings that scanner severity cannot. The baseline ties 16 of the 21 scenario pairs; the framework orders 19 and inverts 0.
  • A declared business context reaches the ranking faithfully, and every point of every score is attributable to a named factor.
  • The ordering results are stable across the registered perturbations (59 of 63 for the pairs).
  • Exposure and privilege move the ranking in the predicted direction where they resolve: on the hand-crafted cases and in the networking scenario.

Not supported

  • Any claim about how many alerts are saved. The Critical/High count ranges from 19 to 581 as one boundary moves two points either way.
  • That the encryption factor works. Both of its pairs tie.
  • That most of the ordering is derived from code. 9 of 19 correct scenario pairs and 4 of 8 passing pairs rest on declared context alone.
  • External validity. The expected orderings were reviewed by an automated reviewer, not a human expert, and the corpus is two teaching repositories.
  • Behaviour at the top of the range. No finding reaches Critical.
